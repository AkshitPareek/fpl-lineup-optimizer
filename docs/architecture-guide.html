2026 Architecture Brief

FPL Lineup Optimizer

A white-paper style narrative that captures how the optimizer moves data from the FPL cloud through ML-enhanced predictors into transfer-grade decisions.

One Liner

Data ingestion → prediction services (rule-based + ML) → MILP planning (single/multi/robust) → analytics + chip guidance → curated API for the frontend. Designed for observability, optional ML, and graceful fallbacks.

System Layers

Data Fabric

  • FPLService caches `/bootstrap-static`, `/fixtures`, manager picks, chips, ownership for ~1hr so we amortize API calls.
  • HistoricalDataService persists element-summary data under `data/cache/all_player_history.json` to reconstruct past GWs and power ML feature engineering.
  • Fixture metadata drives `FixtureAnalyzer`, enabling DGW/BGW detection, FDR averages, and tickers used by chips, analytics, and front-end labels.

Prediction Stack

  • Rule-based `PointPredictor`: xG/xA proxies, ICT/CBIT/CBIRT bonuses, fixture difficulty, ownership adjustments, optional Understat enrichments.
  • ML `MLPredictor`: loads `models/current` artifacts (metadata, scaler, XGB/NN weights, `feature_columns.csv`), extracts engineered features (form, minutes, fixtures, health) from bootstrap + history, ensembles XGB+NN outputs, returns confidence.
  • Blend logic in `backend/main.py` uses `ml_blend_weight` with graceful fallback when `confidence == 30` or ML fails; rule-predictions always available as backup.

Optimization Engines

  • `FPLOptimizer`: single GW LP maximizing 0.9×starters + 0.1×bench, enforces budget, squad/starter counts, per-team cap, and strategy-specific boosts (safe/differential/transfers/my_squad).
  • `MultiPeriodFPLOptimizer`: 3-8 GW rolling horizon, transfer banking (≤5 FTs), hit penalties, chip activation (Wildcard/Free Hit/Triple Captain/Bench Boost), captain + vice nearly gameweek aware.
  • `RobustOptimizer`: box uncertainty (σ derived from XP × √(1−R²)), γ-level hedging, same positional/budget constraints as base solver but built for worst-case.

Core APIs

Optimization Suite

Endpoints include `/api/optimize`, `/api/optimize/compare`, `/api/optimize/multi-period`, and `/api/optimize/robust`—all routed through `backend/main.py`.

Multi-period accepts ML blend flags, chips, banked transfers, strategy toggles.

Analytics

/api/ev/*, /api/ownership/*, and /api/live/* deliver EV dashboards, ownership diffs, and live trends used by `frontend/src/components/analytics`.

Chip & Backtest

Chip recommendations (`/api/chip-suggestions`) reuse `ChipAdvisor`. Backtests and SSE streams rely on `BacktestEngine` to replay past GWs.

Operational Notes

Observability

  • Startup logs announce CORS and origins.
  • Multi-period logs include `force_next_gameweek` overrides and ML blend metadata.
  • Exceptions push tracebacks plus analytics enrichment errors.

Fallbacks

  • ML path uses confidence; predictions with 30 trigger fallbacks documented in the team playbook.
  • If ML errors, blending defaults to rule values; `MLPredictor.predict_batch` returns baseline with confidence=30.
  • `use_ml_predictions` remains a request-level opt-in flag until frontend surfaces it.
